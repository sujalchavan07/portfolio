From C Pointers to Java OOP: How This Course Changed the Way I Architect Software

When I started our second-year Java Programming course at JSPM University, my mindset was still rooted in first-year procedural C programming—writing long functions and passing structs around manually. During the first few lab sessions, creating separate classes, interfaces, and getters/setters felt like extra ceremony.

The turning point came when I began building my course mini-project, a Cybersecurity Threat Analyzer. As the program grew to handle multiple log formats, firewall rules, and severity alerts, procedural code would have become unmaintainable. By applying abstraction, inheritance, and polymorphism, I designed a clean ThreatDetector interface where new detection modules plugged in without touching existing code. Combining custom classes with the Java Collections Framework (`PriorityQueue` and `HashMap`) made sorting high-risk security threats effortless.

Key Learnings & Memorable Moments:

  • Encapsulation Protects State: Keeping fields private prevented accidental bugs across multi-file modules.
  • Collections & Generics Save Time: Mastering `ArrayList`, `HashMap`, and `PriorityQueue` bridged theory from Data Structures directly into practical apps.
  • Exception Handling Builds Resilience: Writing custom checked exceptions made my file-parsing utilities crash-proof.

What I will do differently next: Moving forward, I will sketch UML class diagrams before writing a single line of Java code and expand my mini-project into a full Spring Boot microservice.

CyberGuard Java: Enterprise Firewall Log & Cybersecurity Threat Analyzer

Problem Statement (The "Why")

Small campus networks and junior system administrators often struggle to spot brute-force SSH attacks, SQL injection payloads, and port-scanning anomalies buried inside thousands of raw firewall log lines. Existing enterprise SIEM tools are resource-heavy and complex, creating a need for a lightweight, object-oriented Java threat analyzer that parses logs, scores risk severity in real time, and generates actionable firewall block rules.

How It Works (Architecture & Description)

Built completely in core Java 17+, CyberGuard ingests simulated or real server access/firewall logs via `BufferedReader` streams. Each log entry is encapsulated into an immutable `PacketLog` object and evaluated against polymorphic `ThreatRule` implementations (`BruteForceDetector`, `SqlInjectionDetector`, `PortScanDetector`). Detected threats are pushed into a custom-weighted `PriorityQueue` so critical CVSS-9+ incidents surface immediately at the top of the report.

Java & OOP Concepts Used
  • Interfaces & Runtime Polymorphism (`ThreatRule`)
  • Encapsulation & Custom `Comparable`
  • Java Collections (`PriorityQueue`, `HashMap`)
  • Custom Exception Handling & File I/O (`NIO`)
  • Regex Pattern Matching (`java.util.regex`)
Key Features Built
  • Real-time IP brute-force frequency counter
  • Automated CVSS severity risk scoring (1–10)
  • Auto-generation of `iptables` firewall drop rules
  • Exportable Incident Summary Report (`.txt`/CLI)
  • Zero external dependencies (Pure JDK)

Entry #2: Data Structure Assignment (Java) Custom Stack, Linked List & Min-Heap Dijkstra
GitHub Repo

SmartRoute DSA: Travel Itinerary Undo-Stack, Doubly Linked List & Shortest-Path Engine

Problem Statement (The "Why")

Inspired by our team's Travel Planning Application, travelers frequently add, reorder, or undo multi-city stops while needing the lowest-cost transit path between destinations. Standard array lists make frequent middle insertions and multi-step undo/redo operations inefficient, calling for a custom-built Java Data Structures engine combining a Doubly Linked List, LIFO Stack, and Priority Queue Graph router.

How It Works (Data Structures Implementation)

Implemented from scratch in Java without relying on built-in library shortcuts for the core structures: (1) A custom `DoublyLinkedList` stores the active travel itinerary with $O(1)$ head/tail insertion; (2) Two generic `CustomStack` instances (`undoStack` and `redoStack`) provide instant state rollback; and (3) An Adjacency List graph paired with a Min-Heap computes the shortest travel distance across Maharashtra cities using Dijkstra's Algorithm.

Data Structures Implemented
  • Generic LIFO `Stack` (Undo / Redo Engine)
  • Custom `DoublyLinkedList` (Itinerary Chain)
  • Weighted Graph (Adjacency List + Min-Heap)
  • MergeSort for sorting stops by budget/time
Key Features & Complexity
  • $O(1)$ Push/Pop state reversal for trip edits
  • $O((V + E) \log V)$ Dijkstra shortest route
  • Forward & backward itinerary traversal
  • Interactive menu-driven CLI verification
